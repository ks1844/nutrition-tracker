## 1. 共通仕様

| 項目 | 規則 |
|------|------|
| ベース URL | `http://localhost:8080/api`（ヘルスチェックのみ `GET /health` → `{"status":"ok"}`） |
| 形式 | REST / JSON（UTF-8）。プロパティ名は **camelCase** |
| 認証 | なし（D-1。サーバーが固定ユーザーに解決する。Q-6） |
| 日付 | `yyyy-MM-dd`（`eatenOn` など）。日時は ISO-8601 |
| 数値 | 栄養値・重量・割合は JSON の number（保存値の桁数。丸め規則は [03.栄養計算仕様.md §5](03.栄養計算仕様.md)）。サーバー内部は `decimal`（C#） |
| 栄養素の指定 | `nutrients` の `code`（[04.データモデル.md §5](04.データモデル.md)） |
| 栄養値の配列 | `[{ "code": "PROT", "amount": 91.34, "isIncomplete": false }]`（`displayOrder` 順） |
| 空値 | 未設定は `null` を明示する（プロパティを省略しない） |
| ID | 数値（`bigint`） |
| ページング | 食材検索のみ `limit`（既定 20、最大 50）/ `offset`。他は全件（MVP） |
| 日付の区切り | 暫定: 0:00。`eatenOn` は利用者が指定する（Q-5） |

### 1.1 ステータスコード

| コード | 用途 |
|--------|------|
| 200 | 取得・更新成功（本文あり） |
| 201 | 作成成功（本文あり。`Location` ヘッダー付き） |
| 204 | 削除成功（本文なし） |
| 400 | 入力不正（形式・範囲・必須・列挙値） |
| 404 | 対象が存在しない（論理削除済みメニューを含む） |
| 409 | 現在の状態と矛盾する操作（無効化された食材の使用、コピー先に既に記録がある 等） |
| 500 | 想定外のサーバーエラー（詳細はログのみ。本文にスタックトレースを出さない） |

### 1.2 エラー形式

```json
{
  "code": "VALIDATION_ERROR",
  "message": "入力内容に誤りがあります",
  "details": [
    { "field": "items[0].quantity", "reason": "0より大きい値を指定してください" }
  ]
}
```

| `code` | HTTP | 備考 |
|--------|------|------|
| `VALIDATION_ERROR` | 400 | `details` に項目ごとの理由。`field` は JSON パス |
| `NOT_FOUND` | 404 | `details` は空配列 |
| `CONFLICT` | 409 | `details[].reason` に機械可読の理由コード（例: `FOOD_INACTIVE`, `TARGET_DATE_HAS_RECORDS`） |
| `INTERNAL_ERROR` | 500 | `details` は空配列 |

- `message` は日本語の利用者向け文言。`details` は常に配列（空でも省略しない）。
- 100% 超過（FR-034）はエラーではなく、成功レスポンスの `warnings` で返す。

## 3. 食材・栄養素

### API-01 `GET /api/foods`

| クエリ | 必須 | 説明 |
|--------|------|------|
| `q` | ○ | 検索語（前後の空白を除去して 1 文字以上、50 文字以内） |
| `limit` / `offset` | – | 既定 20 / 0。`limit` 最大 50 |

- 検索語を正規化（全角/半角、ひらがな⇔カタカナ）し、`name` / `読み仮名` / `T食材別名.alias` のいずれかに部分一致する**有効な**食材（`有効フラグ`）を返す。名前の前方一致を優先して並べる。
- 400: `q` が空/長すぎる。

```json
{
  "items": [
    { "id": 1, "foodCode": "T001", "name": "にんじん", "nameKana": "にんじん",
      "foodGroup": "野菜類", "refuseRatePct": 10.0,
      "units": [{ "id": 10, "unitName": "本", "gramsPerUnit": 150.0, "isDefault": true }] }
  ],
  "total": 1
}
```

### API-02 `GET /api/foods/{id}`

食材の全栄養素（`per100g` は未測定なら `null`）、換算単位、別名、`sourceVersion` を返す。404: 存在しない（無効食材は取得可）。

```json
{
  "id": 3, "foodCode": "T003", "name": "みそ", "officialName": null, "nameKana": "みそ",
  "foodGroup": "調味料類", "refuseRatePct": 0.0, "sourceVersion": "(Q-1 確定後)", "isActive": true,
  "aliases": ["味噌"],
  "units": [{ "id": 30, "unitName": "大さじ", "gramsPerUnit": 18.0, "isDefault": true }],
  "nutrients": [
    { "code": "PROT", "per100g": 12.0, "isTrace": false, "sourceNote": null },
    { "code": "VITC", "per100g": null, "isTrace": false, "sourceNote": null }
  ]
}
```

### API-03 `GET /api/nutrients`

```json
[ { "code": "PROT", "nameJa": "タンパク質", "unit": "g", "category": "macro", "isReference": false, "displayOrder": 2 } ]
```

## 4. プロフィール

### API-04 `GET /api/profile` / API-05 `PUT /api/profile`

- GET: 未登録なら 404（`NOT_FOUND`。画面は SCR-01 へ誘導）。
- PUT: 登録/更新（upsert）。成功時 200（初回も 200）。

リクエスト（PUT）:

```json
{ "sex": "male", "birthDate": "1996-04-01", "heightCm": 170.0, "weightKg": 65.0,
  "activityLevel": 2, "goal": "skin", "energyTargetKcal": null }
```

レスポンス（GET/PUT 共通）: リクエスト項目に加え、算出目標（式は [06.スコアリング仕様.md §2](06.スコアリング仕様.md)）。

```json
{ "...": "（リクエスト項目）",
  "targets": {
    "energyKcal": { "auto": 2155, "override": null, "effective": 2155 },
    "proteinG": 65.0,
    "nutrients": [ { "code": "VITC", "kind": "RDA", "amount": 100.0, "basis": "PER_DAY" } ]
  } }
```

| 項目 | バリデーション（400） |
|------|------------------------|
| `sex` | `male` / `female` |
| `birthDate` | 過去日 |
| `heightCm` | 50.0〜250.0（暫定） |
| `weightKg` | 20.0〜300.0（暫定） |
| `activityLevel` | 1〜4 |
| `goal` | `skin` / `muscle` / `both` |
| `energyTargetKcal` | `null` または 500〜10000 の整数（暫定） |

`targets.nutrients` は `T栄養目標` のうち、性別が一致または `all` で、年齢（今日時点）が範囲内の行だけを返す（`amount` は常に数値）。`T栄養目標` が未投入（Q-2）の間は空配列。

## 5. メニュー

### 共通: メニューのリクエスト（API-07 / API-09 / API-12 の `items`）

```json
{ "name": "豚汁", "cookedOn": "2026-10-14", "memo": null,
  "cookedTotalWeightG": 2400.0, "servings": 8.0, "servingLabel": "お椀",
  "items": [
    { "foodId": 1, "unitId": 10,   "quantity": 2 },
    { "foodId": 2, "unitId": null, "quantity": 400 },
    { "foodId": 3, "unitId": 30,   "quantity": 4 }
  ] }
```

- `unitId` が `null` なら `quantity` は g。単位指定なら `amountG = quantity × gramsPerUnit`（保存時に `DECIMAL(8,2)` へ、[03.栄養計算仕様.md §2](03.栄養計算仕様.md)）。
- 並び順は配列順（`sortOrder` はサーバーが採番）。

| 項目 | バリデーション（400） / 409 |
|------|------------------------------|
| `name` | 必須、1〜100 文字 |
| `cookedTotalWeightG` | 0 より大きい、小数 1 桁、`DECIMAL(8,1)` に収まる |
| `servings` | 0 より大きい、小数 1 桁 |
| `servingLabel` | 省略時「お椀」、20 文字以内 |
| `items` | 1 件以上。`quantity` > 0。`unitId` はその `foodId` の単位であること |
| `memo` | 500 文字以内 |
| 食材 | 存在しない → 400（`items[n].foodId`）。**無効化（`有効フラグ=false`）→ 409 `FOOD_INACTIVE`** |

### API-06 `GET /api/menus`

論理削除されていないメニューを新しい順に返す。

```json
[ { "id": 5, "name": "豚汁", "cookedOn": "2026-10-14", "cookedTotalWeightG": 2400.0,
    "servings": 8.0, "servingLabel": "お椀", "servingWeightG": 300.0,
    "remaining": { "ratio": 0.6875, "servings": 5.5, "isOver": false } } ]
```

`remaining` = [03.栄養計算仕様.md §6](03.栄養計算仕様.md)。`ratio` が 0 未満のとき `isOver: true`。

### API-07 `POST /api/menus`（201）

リクエストは上記。レスポンスは API-08 と同じ。

### API-08 `GET /api/menus/{id}`（200 / 404）

```json
{ "id": 5, "name": "豚汁", "cookedOn": "2026-10-14", "memo": null,
  "cookedTotalWeightG": 2400.0, "servings": 8.0, "servingLabel": "お椀", "servingWeightG": 300.0,
  "items": [ { "id": 51, "foodId": 1, "foodName": "にんじん", "unitId": 10, "unitName": "本",
               "quantity": 2, "amountG": 300.0, "sortOrder": 0 } ],
  "nutrients": [ { "code": "PROT", "amount": 91.34, "isIncomplete": false },
                 { "code": "VITC", "amount": 31.0, "isIncomplete": true } ],
  "perServing": [ { "code": "PROT", "amount": 11.4175, "isIncomplete": false } ],
  "remaining": { "ratio": 0.6875, "servings": 5.5, "isOver": false } }
```

### API-09 `PUT /api/menus/{id}`（200 / 400 / 404 / 409）

全項目置換。**過去の記録は変わらない**（スナップショット保存済み。[ADR-0002](adr/0002-栄養スナップショット.md)）。論理削除済みは 404。

### API-10 `DELETE /api/menus/{id}`（204 / 404）

論理削除（`削除日時` を設定）。記録済みの `T食事記録項目` は残る。

### API-11 `POST /api/menus/{id}/duplicate`（201 / 404）

本文は任意: `{ "name": "豚汁のコピー", "cookedOn": "2026-10-17" }`。省略時、名前は「<元の名前>のコピー」、`cookedOn` は当日。食材・完成後重量・杯数・メモを複製。記録は複製しない。レスポンスは API-08 と同じ。

### API-12 `POST /api/menus/preview`（200 / 400）

未保存の入力から栄養を計算する（DB 更新なし）。`name`・`cookedTotalWeightG`・`servings` は任意（`cookedTotalWeightG` と `servings` の両方があるときだけ `servingWeightG` と `perServing` を返し、無いときは `null`）。食材の無効化は 409 ではなく**警告**（プレビューのため）。その他の入力検証は作成（API-07）と同じ（違反は 400）。

```json
{ "items": [ { "foodId": 1, "foodName": "にんじん", "amountG": 300.0, "edibleG": 270.0,
               "nutrients": [ { "code": "PROT", "amount": 2.7, "isIncomplete": false } ] } ],
  "nutrients": [ { "code": "PROT", "amount": 91.34, "isIncomplete": false },
                 { "code": "VITC", "amount": 31.0, "isIncomplete": true },
                 { "code": "VITA_RAE", "amount": 1930.0, "isIncomplete": false } ],
  "servingWeightG": 300.0,
  "perServing": [ { "code": "PROT", "amount": 11.4175, "isIncomplete": false } ],
  "warnings": [] }
```

- `items[].nutrients` は丸め前の値を 4 桁 HALF_UP で出力するだけ（参考表示）。合計は丸め前の厳密値から 1 回だけ丸める。
- `warnings[]` は `{ "code": "FOOD_INACTIVE", "foodId": 2, "message": "…は無効になっている食材です" }`（食材ごとに 1 件）。
- 正解値: [03.栄養計算仕様.md §9](03.栄養計算仕様.md)。

## 6. 食事記録

### 記録リクエスト（API-14 / API-15）

```json
{ "eatenOn": "2026-10-17", "mealType": "dinner", "memo": null,
  "items": [
    { "menuId": 5, "inputMode": "SERVING", "inputValue": 1.5 },
    { "foodId": 9, "unitId": null, "inputMode": "GRAM", "inputValue": 150 }
  ] }
```

| 項目 | バリデーション（400） / 409 |
|------|------------------------------|
| `eatenOn` | 必須 |
| `mealType` | `breakfast` / `lunch` / `dinner` / `snack` |
| `items` | 1 件以上。各項目は `menuId` と `foodId` の**どちらか一方のみ**（両方/無し → 400） |
| `inputMode`（メニュー） | `RATIO` / `SERVING` / `GRAM`。`inputValue` > 0 |
| `inputMode`（食材） | `GRAM` / `UNIT`。`UNIT` は `unitId` 必須（その食材の単位）。`inputValue` > 0 |
| メニュー | 存在しない/論理削除済み → 404 ではなく **400**（`items[n].menuId`）。※更新時の既存項目は削除済みメニューでも保持可 |
| 食材 | 無効化 → 409 `FOOD_INACTIVE` |

### API-13 `GET /api/meal-records?date=`（200）

`date` 必須。その日の記録を食事区分順に返す。

```json
{ "date": "2026-10-17",
  "records": [ { "id": 100, "eatenOn": "2026-10-17", "mealType": "dinner", "memo": null,
    "items": [ { "id": 1001, "menuId": 5, "menuName": "豚汁", "foodId": null, "foodName": null, "unitId": null,
                 "inputMode": "SERVING", "inputValue": 1.5, "portionRatio": 0.1875, "amountG": null,
                 "nutrients": [ { "code": "PROT", "amount": 17.1263, "isIncomplete": false } ] } ] } ] }
```

`nutrients` は**保存済みスナップショット**（丸め済み 4 桁）。`unitId` は食材を `UNIT` で入力したときの単位（編集画面で入力を再表示するため。それ以外は `null`）。

### API-14 `POST /api/meal-records`（201）

サーバーが `portionRatio` / `amountG` を決め（[03.栄養計算仕様.md §6, §7](03.栄養計算仕様.md)）、栄養スナップショットを保存する。レスポンスは API-13 の `records[]` 1 件 + `warnings`。

```json
{ "...": "（記録 1 件）",
  "warnings": [ { "code": "MENU_OVER_100PCT", "menuId": 5, "totalPortionRatio": 1.0625,
                  "message": "豚汁の記録が合計100%を超えています" } ] }
```

- 警告は保存を妨げない（FR-034）。`totalPortionRatio` は当該メニューの全有効記録の `portionRatio` 合計（今回分を含む）。
- `inputValue` は小数 3 桁（HALF_UP）で保存する。丸めた結果、割合（小数 6 桁）や重さ（小数 2 桁）が 0 になる極小の値は 400（`items[n].inputValue`）。
- 201 の `Location` ヘッダーは `/api/meal-records?date=<eatenOn>`。

### API-15 `PUT /api/meal-records/{id}`（200 / 400 / 404）

全項目置換。入力が変わった項目はスナップショットを**再計算して置換**（[03.栄養計算仕様.md §8](03.栄養計算仕様.md)）。404: 存在しない。

- 「入力が同じ」= `menuId` / `foodId` / `unitId` / `inputMode` / `inputValue` がすべて既存の項目と一致すること（項目の `id` は送らない）。同じ項目は既存の行（`id` とスナップショット）をそのまま残し、削除済みメニュー・無効な食材でも保持できる。
- 一致しない既存項目は削除され、新しい項目は追加される（項目の並びは `id` 順で、リクエストの並び順は保持しない）。
- レスポンスは API-14 と同じ（`warnings` は置換後の合計で判定）。

### API-16 `DELETE /api/meal-records/{id}`（204 / 404）

物理削除（項目・スナップショットはカスケード）。

### API-20 `GET /api/recent-items?limit=`（200）

`limit` 既定 10（最大 30。1 未満は 400）で、メニュー・食材それぞれの件数。直近の記録（食事日の新しい順）から重複を除いて返す。論理削除/無効のものは除く。

```json
{ "menus": [ { "menuId": 5, "name": "豚汁", "lastInputMode": "SERVING", "lastInputValue": 1.5, "lastUsedOn": "2026-10-17" } ],
  "foods": [ { "foodId": 9, "name": "ご飯", "lastInputMode": "GRAM", "lastInputValue": 150, "unitId": null, "lastUsedOn": "2026-10-17" } ] }
```

### API-21 `POST /api/meal-records/copy`（201 / 400 / 409）

```json
{ "fromDate": "2026-10-16", "toDate": "2026-10-17", "allowExisting": false }
```

- `fromDate` の全記録を `toDate` にコピーする。**現在のメニュー/食材の内容で再計算**してスナップショットを作る。
- 論理削除/無効のものはスキップし、レスポンスの `skipped` に載せる。記録の項目がすべてスキップされた食事は作らない。全記録は 1 回の保存で作る（途中で失敗したら 1 件も作られない）。
- `toDate` に記録があり `allowExisting=false` → 409 `TARGET_DATE_HAS_RECORDS`。`fromDate` に記録が無い → 400。`fromDate == toDate` → 400。

```json
{ "records": [ { "...": "作成された記録" } ],
  "skipped": [ { "menuId": 7, "foodId": null, "reason": "MENU_DELETED" },
               { "menuId": null, "foodId": 9, "reason": "FOOD_INACTIVE" } ] }
```

## 7. ダッシュボード

状態判定（栄養素ごと）: `DEFICIENT`（達成率 < 1.0）/ `ACHIEVED`（達成率 = 1.0）/ `OVER_UL`（UL 超過）/ `NO_TARGET`（目標未設定）。表示は色だけにしない（NFR-004）。

### API-17 `GET /api/dashboard/daily?date=`（200 / 400 / 404）

`date` 必須。プロフィール未登録は 404。

```json
{ "date": "2026-10-17", "hasRecords": true,
  "energy": { "intakeKcal": 1420, "targetKcal": 2155, "achievementRate": 0.659026 },
  "pfc": { "proteinG": 62.0, "fatG": 40.0, "carbG": 180.0,
           "ratioPct": { "p": 19, "f": 27, "c": 54 } },
  "scores": {
    "beauty": { "value": 81, "band": "GOOD",  "insufficientData": false, "hasIncomplete": false },
    "muscle": { "value": 75, "band": "FAIR",  "insufficientData": false, "hasIncomplete": false },
    "base":   { "value": 62, "band": "FAIR",  "insufficientData": false, "hasIncomplete": true } },
  "nutrients": [ { "code": "VITC", "nameJa": "ビタミンC", "unit": "mg", "intake": 78.0,
      "target": { "kind": "RDA", "min": null, "max": null, "ul": null, "basis": "PER_DAY", "amount": null },
      "achievementRate": 0.78, "status": "DEFICIENT", "isIncomplete": false, "isReference": false } ],
  "remainingMenus": [ { "menuId": 5, "name": "豚汁", "remainingRatio": 0.6875, "remainingServings": 5.5, "servingLabel": "お椀" } ],
  "notices": [ { "code": "INCOMPLETE_NUTRIENT", "nutrientCodes": ["VITC"] } ] }
```

- 日次の `scores` は「今日の進捗」（[06.スコアリング仕様.md §1.3](06.スコアリング仕様.md)）。`band`: `GOOD` / `FAIR` / `LOW`。記録が無い日、または目標が無くて算出できないスコアは `value`/`band` が `null`。
- 数値例は説明用（目標値は Q-2 確定後に入る）。`target.amount` は未転記の間 `null` → `status: NO_TARGET`。
- `energy.achievementRate` は頭打ちしない（摂取 ÷ 目標、小数 6 桁）。栄養素の `achievementRate` は下限型の目標があるときだけ返し、100% で頭打ち（`null` = 下限型の目標なし）。
- `target`: `kind`/`amount` は下限型（`RDA` > `AI` > `DG_MIN` の順に 1 つ）。`min`/`max`/`ul` は `DG_MIN`/`DG_MAX`/`UL`。体重あたり（`PER_KG_BW`）は体重を掛けて 1 日あたり（`basis` は常に `PER_DAY`）に換算する。エネルギー比（`PCT_ENERGY`）は未対応で、目標なしとして扱う（暫定）。エネルギー・タンパク質は `T栄養目標` ではなくプロフィールから算出し、`kind` は `CALCULATED`。
- `status`: 上限（`ul`、無ければ `max`）を超えると `OVER_UL`（`DG_MAX` の超過も含む）。下限型の目標があれば達成率 < 1.0 で `DEFICIENT`、1.0 で `ACHIEVED`。上限しかない栄養素（食塩など）は、超えなければ `ACHIEVED`（`achievementRate` は `null`）。目標が何もなければ `NO_TARGET`。
- `isIncomplete` は参考値の栄養素（`ASTX`）では常に `false`。
- `remainingMenus` は残量（`remainingRatio`）が 0 より大きいメニューを新しい順に返す（食べきった・超過したものは含めない）。
- 日付ごとの年齢（目標の引き当て）は、指定した `date` 時点の満年齢。
- 免責文は画面側の固定文言（FR-047）。

### API-18 `GET /api/dashboard/weekly?endDate=`（200 / 400 / 404）

`endDate` 必須（未来日は 400）。窓 = `endDate−6`〜`endDate`。

```json
{ "endDate": "2026-10-17", "windowStart": "2026-10-11", "recordDays": 5, "insufficientData": false,
  "averages": { "energy": { "intakeKcal": 1850, "targetKcal": 2155 }, "pfc": { "...": "..." },
                "nutrients": [ { "code": "VITC", "intake": 70.0, "achievementRate": 0.7, "status": "DEFICIENT",
                                 "isIncomplete": false, "ulExceededDays": 0 } ] },
  "scores": { "beauty": { "value": 78, "band": "FAIR", "insufficientData": false, "hasIncomplete": false },
              "muscle": { "...": "..." }, "base": { "...": "..." } },
  "series": [ { "date": "2026-10-11", "hasRecords": true, "intakeKcal": 1900,
                "scores": { "beauty": 80, "muscle": 72, "base": 65 } } ],
  "remainingMenus": [ { "menuId": 5, "name": "豚汁", "remainingRatio": 0.6875, "remainingServings": 5.5, "servingLabel": "お椀" } ],
  "notices": [] }
```

- `recordDays < 3` → `insufficientData: true`、`scores` の各 `value` は `null`（`insufficientData` も `true`）（FR-046）。`averages` は記録日が 1 日以上あれば返す（記録日 0 のときだけ `energy`/`pfc` が `null`、`nutrients` が空配列）。
- `averages` は記録のある日だけの平均（記録日で割る。7 で割らない）。`nutrients[].ulExceededDays` は窓内で上限（`ul`、無ければ `max`）を超えた日数。`status` は平均値で判定する。
- `series` は 7 件固定。記録の無い日は `hasRecords: false`、`intakeKcal` と `scores` は `null`（0 にしない）。日ごとのスコアはその日 1 日分の摂取量で計算する。
- 筋肉スコアの分配率は、窓内の朝・昼・夕の食事すべてに対する割合。
- `remainingMenus`・`notices` は日次（API-17）と同じ形（`notices` は平均値に未測定が含まれる栄養素）。

### API-19 `GET /api/nutrients/{code}/contributions?from=&to=`（200 / 400 / 404）

`from` ≤ `to`、期間は最大 31 日。404: 栄養素コードが存在しない。

```json
{ "nutrientCode": "PROT", "from": "2026-10-11", "to": "2026-10-17", "totalAmount": 410.2, "isIncomplete": false,
  "items": [ { "type": "MENU", "id": 5, "name": "豚汁", "amount": 51.2, "sharePct": 12.5,
               "children": [ { "foodId": 2, "name": "豚こま肉", "amount": 22.4 } ] },
             { "type": "FOOD", "id": 9, "name": "ご飯", "amount": 3.7, "sharePct": 0.9, "children": [] } ] }
```

- `items` は期間内の記録項目のスナップショットを、メニュー・単品食材ごとに集計したもの（同じメニュー・食材は 1 件にまとめる。寄与の大きい順で、寄与が 0 のものは含めない）。`amount` は栄養素の単位で小数 1 桁（kcal は整数）、`sharePct` は小数 1 桁。
- `children` はメニューの**現在の構成**で、期間内に食べた割合の合計を掛けて按分した参考値（暫定。記録後にメニューを編集した場合は実際とずれうる）。食材ごとに 1 件で、寄与が 0（未測定を含む）の食材は含めない。
- 削除済みのメニューも、過去の記録の寄与として含める。`from`/`to` が無い・`from` > `to`・31 日を超える → 400。

## 8. 非機能に関する取り決め

| 項目 | 内容 |
|------|------|
| 性能 | 各 API は食材 300・記録 1 年分で 1 秒以内（NFR-002）。`T食事記録(ユーザーID, 食事日)` の索引を前提にする |
| 冪等性 | PUT/DELETE は冪等。POST は冪等でない（二重送信はクライアントで抑止） |
| CORS | 開発時は Angular 開発サーバーのプロキシ（`proxy.conf.json`。`/api` → `localhost:8080`）で回避する |
| 機密 | レスポンスにスタックトレース・内部 ID 以外の内部情報を含めない |
