# 用語集

- 状態: ドラフト / 最終更新: 2026-10-17
- 索引: [README.md](README.md)

「識別子」列は、DB は日本語の物理名（テーブルは `T`＋日本語名。[05.テーブル定義書.md](05.テーブル定義書.md)）、API は camelCase、C# は PascalCase（[12.アーキテクチャ.md §4](12.アーキテクチャ.md)）。区分値・コード値は英語のまま。

## 1. 食材・栄養

| 日本語 | 識別子（DB／API／C#） | 定義 |
|--------|--------------|------|
| 食材 | `T食材` / `Food` | 食品成分表に基づくマスタの 1 件。利用者は追加できない |
| 食品コード | `食品コード` / `foodCode` | 食材の外部コード（文字列）。取り込みの冪等キー |
| 栄養素 | `T栄養素` / `Nutrient` | 管理対象の栄養成分。コード一覧は [04.データモデル.md §5](04.データモデル.md) |
| 栄養素コード | `T栄養素.栄養素コード` / `code` | `PROT` など。API・CSV・設定で栄養素を指す識別子 |
| 100g あたり含有量 | `100gあたり含有量` / `per100g` | 可食部 100g あたりの栄養素量 |
| 廃棄率 | `廃棄率` / `refuseRatePct` | 廃棄部（皮・種など）の割合（%）。可食部 = 重量 ×（1 − 廃棄率/100） |
| 可食部 | – | 廃棄部を除いた食べられる部分 |
| 廃棄前重量 | – | 皮などを含む購入時の重量。**アプリの入力は全てこの重量** |
| 換算単位 | `T食材単位` | 「1 本」「大さじ」など。1 単位あたりの g を持つ（廃棄部込み） |
| 1 単位あたりグラム | `1単位あたりグラム` | 換算単位 1 つの重量（廃棄部込み） |
| 欠測（未測定） | `100gあたり含有量` が NULL | 成分表で「-」の項目。0 とは区別する |
| 微量 | `微量フラグ` / `isTrace` | 成分表で「Tr」。値は 0 とし、フラグを立てる |
| 栄養不完全 | `不完全フラグ` / `isIncomplete` | 未測定の食材を含むため、合計が実際より少ない可能性がある印 |
| 参考値 | `参考値フラグ` / `isReference` | 出典が成分表以外の栄養素（例: ASTX）。スコアに含めない |
| 出典・版 | `出典版`, `出典メモ` / `sourceVersion`, `sourceNote` | 成分値の出典と版（NFR-008） |

## 2. メニュー・記録

| 日本語 | 識別子（DB／API／C#） | 定義 |
|--------|--------------|------|
| メニュー | `Tメニュー` / `Menu` | 作り置きの料理 1 品。食材リストと完成後重量・杯数を持つ |
| メニュー食材 | `Tメニュー食材` | メニューを構成する食材と量。換算済み g（`重量g` / `amountG`）が正 |
| 完成後重量 | `完成後重量g` / `cookedTotalWeightG` | 調理後の料理全体の重量。鍋ごとの重さ − 空鍋の重さ |
| 杯数 | `杯数` / `servings` | メニュー全体を何杯分と定義したか |
| 杯ラベル | `杯ラベル` / `servingLabel` | 「お椀」「皿」など杯の呼び名 |
| 1 食分 | – | 食べた量 ÷ 完成後重量で表す割合（D-4） |
| 食べた割合 | `食べた割合` / `portionRatio` | メニュー全体に対する食べた割合。1 を超えてもよい。DECIMAL(9,6) |
| 入力方式 | `入力方式` / `inputMode` | `RATIO`（割合）/ `SERVING`（杯数）/ `GRAM`（g）/ `UNIT`（単位） |
| 残量 | – / `remaining` | 1 − Σ `食べた割合`。保存しない |
| 食事記録 | `T食事記録` / `MealRecord` | ある日の 1 食（朝昼夕・間食） |
| 食事区分 | `食事区分` / `mealType` | `breakfast` / `lunch` / `dinner` / `snack` |
| 記録項目 | `T食事記録項目` / `MealRecordItem` | 食事記録内の 1 品（メニューまたは単品食材） |
| 栄養スナップショット | `T食事記録項目栄養素` | 記録時点で確定した栄養値（[ADR-0002](adr/0002-栄養スナップショット.md)） |
| 記録日 | – | 食事記録が 1 件以上ある日 |
| 食べた日 | `食事日` / `eatenOn` | 食事をした日（DATE） |

## 3. 目標・スコア

| 日本語 | 識別子（DB／API／C#） | 定義 |
|--------|--------------|------|
| 活動レベル | `活動レベル` / `activityLevel` | 1〜4（係数は [06.スコアリング仕様.md §2](06.スコアリング仕様.md)） |
| 目的 | `目的` / `goal` | `skin`（美肌）/ `muscle`（筋肉）/ `both`（両方） |
| エネルギー目標 | `エネルギー目標kcal` / `energyTargetKcal` | 自動算出値、または利用者が上書きした値 |
| 栄養目標 | `T栄養目標` / `NutrientTarget` | 栄養素ごとの目標値（`種別`） |
| 目標種別 | `種別` / `kind` | `RDA`（推奨量）/ `AI`（目安量）/ `DG_MIN`（目標量の下限）/ `DG_MAX`（目標量の上限）/ `UL`（耐容上限量） |
| 単位基準 | `単位基準` / `basis` | `PER_DAY` / `PER_KG_BW`（体重あたり）/ `PCT_ENERGY`（エネルギー比） |
| 達成率 | `achievementRate` | 摂取量 ÷ 目標。下限型は 1.0 で頭打ち |
| 下限型 / 範囲型 / 上限型 | – | 目標の種類。下限=RDA/AI/DG_MIN、範囲=DG_MIN+DG_MAX、上限=DG_MAX/UL |
| UL | `UL` | 耐容上限量。超過は警告対象 |
| 美肌スコア | `beautyScore` | [06.スコアリング仕様.md §3](06.スコアリング仕様.md) |
| 筋肉スコア | `muscleScore` | [06.スコアリング仕様.md §4](06.スコアリング仕様.md) |
| 基礎スコア | `baseScore` | [06.スコアリング仕様.md §5](06.スコアリング仕様.md) |
| 分配率 | `distributionRate` | 朝昼夕のうちタンパク質 20g 以上だった食事の割合 |
| データ不足 | `insufficientData` | 7 日平均で記録日が 3 日未満 |
| PFC 比 | `pfcRatio` | タンパク質・脂質・炭水化物のエネルギー比。P,C は 4kcal/g、F は 9kcal/g で算出 |
| 今日の進捗 | – | 当日分のみの達成状況。7 日平均とは別表示 |

## 4. 開発

| 日本語 | 用語 | 定義 |
|--------|------|------|
| 正本 | – | 唯一の根拠となる文書。`docs/` が仕様の正本 |
| 正解データ | golden data | 自動テストの期待値として使う、計算済みの入出力表。実際の成分表の値ではないテスト用ダミー値 |
| ハーネスエンジニアリング | – | 設計書を AI エージェントが読む正本とし、正解データと ID トレースで機械検証できる形にする進め方 |
| 暫定 | – | 根拠が固まっておらず変更されうる値 |
| 作業ブランチ / dev / main | – | Git ブランチ運用。`dev` と `main` には直接コミットしない |
