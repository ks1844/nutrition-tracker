## 1. 凡例・共通事項

### 1.1 命名規則

| 対象 | 規則 | 例 |
|------|------|----|
| テーブル | `T` ＋ 日本語名 | `Tユーザー` |
| カラム | 日本語。主キーは `ID`、外部キーは `<参照先の日本語名>ID` | `ユーザーID` |
| 共通カラム | `作成日時` / `更新日時`（全テーブル） | – |
| 外部キー制約 | `FK_<子>_<親>`（`T` なし） | `FK_食材単位_食材` |
| 一意制約 | `UQ_<表>_<列>` | `UQ_食材_食品コード` |
| 索引 | `IX_<表>_<列>` | `IX_食事記録_ユーザーID_食事日` |
| CHECK 制約 | `CK_<表>_<内容>` | `CK_栄養素_区分` |
| 区分値・コード値 | 英語のまま（§4）。API の契約でもあるため変更しない | `male`, `RATIO`, `PROT` |

識別子は常にバッククォートで囲む（EF Core は自動で囲む。手書き SQL では必須）。`100gあたり含有量` のように数字で始まる名前も、囲めば有効。

### 1.2 型の方針

| 用途 | MySQL | C# | 備考 |
|------|-------|----|------|
| 主キー | `BIGINT AUTO_INCREMENT`（`T栄養素` のみ `SMALLINT AUTO_INCREMENT`） | `long` / `short` | |
| 真偽 | `TINYINT(1)`（0/1） | `bool` | |
| 日付 | `DATE` | `DateOnly` | |
| 日時 | `DATETIME` | `DateTime` | `TIMESTAMP` は 2038 年問題とタイムゾーン変換があるため使わない |
| 栄養値・重量・割合 | `DECIMAL(p,s)` | `decimal` | 浮動小数は使わない（NFR-001）。桁数の根拠は [03.栄養計算仕様.md §5](03.栄養計算仕様.md) |
| 文字列 | `VARCHAR(n)` | `string` | 文字コード `utf8mb4`、エンジン InnoDB |
| 区分値 | `VARCHAR` + `CHECK` | `string`（または enum） | `ENUM` 型は値追加でスキーマ変更が必要になるため使わない |

### 1.3 共通カラム

| 物理名 | 型 | NULL | 既定値 | 説明 |
|--------|----|------|--------|------|
| `作成日時` | DATETIME | NOT NULL | `CURRENT_TIMESTAMP` | 行の作成日時 |
| `更新日時` | DATETIME | NOT NULL | `CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP` | 行の更新日時 |

以降の項目定義表では共通カラムを省略せず末尾に記載する。複合主キーのテーブル（`T食材別名`・`T食材栄養素`・`T食事記録項目栄養素`・`Tユーザープロフィール`）は `ID` 列を持たない。

### 1.4 項目定義表の列

`No` / `物理名` / `型` / `NULL` / `既定値` / `キー`（PK・FK・UK）/ `説明` / `C#`（エンティティのプロパティ名）/ `API`（[09.API仕様.md](09.API仕様.md) の項目名。`–` は API に直接出ない）。

```sql
CREATE TABLE `T栄養素` (
    `ID`           SMALLINT     NOT NULL AUTO_INCREMENT,
    `栄養素コード` VARCHAR(20)  NOT NULL,

    CONSTRAINT `CK_栄養素_区分` CHECK (`区分` IN ('macro','vitamin','mineral','antioxidant'))
```


### 3.4 `T食材栄養素`（V1）

- 用途: 食材ごと・栄養素ごとの 100g あたり含有量。**縦持ち**（[ADR-0003](adr/0003-栄養値の縦持ち.md)）。
- 欠測の表現: `100gあたり含有量` が **NULL = 未測定**（0 とは区別）。`Tr`（微量）は 0 ＋ `微量フラグ`=1（[03.栄養計算仕様.md §4](03.栄養計算仕様.md)）。

| No | 物理名 | 型 | NULL | 既定値 | キー | 説明 | C# | API |
|----|--------|----|------|--------|------|------|----|-----|
| 1 | `食材ID` | BIGINT | NOT NULL | – | PK, FK→`T食材.ID` | 食材 | `FoodId` | – |
| 2 | `栄養素ID` | SMALLINT | NOT NULL | – | PK, FK→`T栄養素.ID` | 栄養素 | `NutrientId` | `code`（コードで返す） |
| 3 | `100gあたり含有量` | DECIMAL(12,4) | NULL | – | | 可食部 100g あたり。NULL = 未測定 | `AmountPer100g` | `per100g` |
| 4 | `微量フラグ` | TINYINT(1) | NOT NULL | 0 | | 1 = Tr（含有量は 0） | `IsTrace` | `isTrace` |
| 5 | `出典メモ` | VARCHAR(200) | NULL | – | | 出典の補足（NFR-008） | `SourceNote` | `sourceNote` |
| 6 | `作成日時` | DATETIME | NOT NULL | 現在日時 | | 共通 | `CreatedAt` | – |
| 7 | `更新日時` | DATETIME | NOT NULL | 現在日時（更新時も） | | 共通 | `UpdatedAt` | – |

| 制約/索引 | 内容 |
|-----------|------|
| 主キー | (`食材ID`, `栄養素ID`) |
| `FK_食材栄養素_食材` / `FK_食材栄養素_栄養素` | RESTRICT |
| `CK_食材栄養素_非負` | `100gあたり含有量 IS NULL OR 100gあたり含有量 >= 0` |
| `CK_食材栄養素_微量` | `微量フラグ = 0 OR COALESCE(100gあたり含有量, -1) = 0`（NULL を通さないため `COALESCE` を使う） |

```sql
CREATE TABLE `T食材栄養素` (
    `食材ID`           BIGINT        NOT NULL,
    `栄養素ID`         SMALLINT      NOT NULL,
    `100gあたり含有量` DECIMAL(12,4) NULL,
    `微量フラグ`       TINYINT(1)    NOT NULL DEFAULT 0,
    `出典メモ`         VARCHAR(200)  NULL,
    `作成日時`         DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `更新日時`         DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`食材ID`, `栄養素ID`),
    CONSTRAINT `FK_食材栄養素_食材`   FOREIGN KEY (`食材ID`)   REFERENCES `T食材` (`ID`),
    CONSTRAINT `FK_食材栄養素_栄養素` FOREIGN KEY (`栄養素ID`) REFERENCES `T栄養素` (`ID`),
    CONSTRAINT `CK_食材栄養素_非負` CHECK (`100gあたり含有量` IS NULL OR `100gあたり含有量` >= 0),
    CONSTRAINT `CK_食材栄養素_微量` CHECK (`微量フラグ` = 0 OR COALESCE(`100gあたり含有量`, -1) = 0)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 3.5 `T食材単位`（V1）

- 用途: 換算単位（「1 本」「大さじ 1」など）。**廃棄部込み**の重さ。食材ごとに別の値（[07.マスタデータ仕様.md §4](07.マスタデータ仕様.md)）。
- 既定単位は食材ごとに高々 1 件。MySQL は部分インデックスに対応していないため、**生成列 `既定一意キー` ＋ UNIQUE** で表現する（NULL は重複扱いにならない）。生成列はアプリから読み書きしない。

| No | 物理名 | 型 | NULL | 既定値 | キー | 説明 | C# | API |
|----|--------|----|------|--------|------|------|----|-----|
| 1 | `ID` | BIGINT AUTO_INCREMENT | NOT NULL | – | PK | 食材単位 ID | `Id` | `units[].id` |
| 2 | `食材ID` | BIGINT | NOT NULL | – | FK→`T食材.ID`, UK(複合) | 食材 | `FoodId` | – |
| 3 | `単位名` | VARCHAR(30) | NOT NULL | – | UK(複合) | 本・個・大さじ 等 | `UnitName` | `unitName` |
| 4 | `1単位あたりグラム` | DECIMAL(8,2) | NOT NULL | – | | 廃棄部込みの g | `GramsPerUnit` | `gramsPerUnit` |
| 5 | `既定フラグ` | TINYINT(1) | NOT NULL | 0 | | 1 = 既定の単位 | `IsDefault` | `isDefault` |
| 6 | `既定一意キー` | BIGINT（生成列・STORED） | NULL | `IF(既定フラグ=1, 食材ID, NULL)` | UK | 既定単位の一意制約用。アプリは使わない | （マッピングしない） | – |
| 7 | `作成日時` | DATETIME | NOT NULL | 現在日時 | | 共通 | `CreatedAt` | – |
| 8 | `更新日時` | DATETIME | NOT NULL | 現在日時（更新時も） | | 共通 | `UpdatedAt` | – |

| 制約/索引 | 内容 |
|-----------|------|
| 主キー | `ID` |
| `FK_食材単位_食材` | `食材ID` → `T食材.ID`（RESTRICT） |
| `UQ_食材単位_食材ID_単位名` | (`食材ID`, `単位名`) |
| `UQ_食材単位_既定一意キー` | `既定一意キー`（食材あたり既定は 1 件） |
| `CK_食材単位_グラム` | `1単位あたりグラム > 0` |

```sql
CREATE TABLE `T食材単位` (
    `ID`               BIGINT       NOT NULL AUTO_INCREMENT,
    `食材ID`           BIGINT       NOT NULL,
    `単位名`           VARCHAR(30)  NOT NULL,
    `1単位あたりグラム` DECIMAL(8,2) NOT NULL,
    `既定フラグ`       TINYINT(1)   NOT NULL DEFAULT 0,
    `既定一意キー`     BIGINT GENERATED ALWAYS AS (IF(`既定フラグ` = 1, `食材ID`, NULL)) STORED,
    `作成日時`         DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `更新日時`         DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`ID`),
    CONSTRAINT `FK_食材単位_食材` FOREIGN KEY (`食材ID`) REFERENCES `T食材` (`ID`),
    CONSTRAINT `UQ_食材単位_食材ID_単位名` UNIQUE (`食材ID`, `単位名`),
    CONSTRAINT `UQ_食材単位_既定一意キー` UNIQUE (`既定一意キー`),
    CONSTRAINT `CK_食材単位_グラム` CHECK (`1単位あたりグラム` > 0)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

| `IX_食事記録項目_食事記録ID` / `IX_食事記録項目_メニューID` | 取得・残量集計用（メニューID の部分インデックスは使えないため通常索引） |

MySQL の制約: **CHECK 制約の対象列は、`CASCADE` などの参照アクションを持つ外部キー列にできない**。そのため CHECK で使う `メニューID`・`食材ID`・`食材単位ID` の外部キーは参照アクションなし（RESTRICT）にしてあり、`CASCADE` を持つ `食事記録ID` は CHECK に使わない。

```sql
CREATE TABLE `T食事記録項目` (
    `ID`         BIGINT        NOT NULL AUTO_INCREMENT,
    `食事記録ID` BIGINT        NOT NULL,
    `メニューID` BIGINT        NULL,
    `食材ID`     BIGINT        NULL,
    `食材単位ID` BIGINT        NULL,
    `入力方式`   VARCHAR(10)   NOT NULL,
    `入力値`     DECIMAL(10,3) NOT NULL,
    `食べた割合` DECIMAL(9,6)  NULL,
    `重量g`      DECIMAL(8,2)  NULL,
    `作成日時`   DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `更新日時`   DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`ID`),
    CONSTRAINT `FK_食事記録項目_食事記録` FOREIGN KEY (`食事記録ID`) REFERENCES `T食事記録` (`ID`) ON DELETE CASCADE,
    CONSTRAINT `FK_食事記録項目_メニュー` FOREIGN KEY (`メニューID`) REFERENCES `Tメニュー` (`ID`),
    CONSTRAINT `FK_食事記録項目_食材`     FOREIGN KEY (`食材ID`)     REFERENCES `T食材` (`ID`),
    CONSTRAINT `FK_食事記録項目_食材単位` FOREIGN KEY (`食材単位ID`) REFERENCES `T食材単位` (`ID`),
    CONSTRAINT `CK_食事記録項目_対象` CHECK ((`メニューID` IS NULL) <> (`食材ID` IS NULL)),
    CONSTRAINT `CK_食事記録項目_入力方式` CHECK (`入力方式` IN ('RATIO','SERVING','GRAM','UNIT')),
    CONSTRAINT `CK_食事記録項目_入力値` CHECK (`入力値` > 0),
    CONSTRAINT `CK_食事記録項目_メニュー` CHECK (`メニューID` IS NULL OR (`入力方式` IN ('RATIO','SERVING','GRAM') AND `食べた割合` IS NOT NULL AND `食べた割合` > 0)),
    CONSTRAINT `CK_食事記録項目_食材` CHECK (`食材ID` IS NULL OR (`入力方式` IN ('GRAM','UNIT') AND `重量g` IS NOT NULL AND `重量g` > 0)),
    INDEX `IX_食事記録項目_食事記録ID` (`食事記録ID`),
    INDEX `IX_食事記録項目_メニューID` (`メニューID`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 3.13 `T食事記録項目栄養素`（V4）

- 用途: 記録時点の**栄養スナップショット**（[ADR-0002](adr/0002-栄養スナップショット.md)）。丸めは保存時に 1 回（小数 4 桁 HALF_UP）。全栄養素分の行を保存し、全食材が未測定の栄養素は `量`=0 ＋ `不完全フラグ`=1。

| No | 物理名 | 型 | NULL | 既定値 | キー | 説明 | C# | API |
|----|--------|----|------|--------|------|------|----|-----|
| 1 | `食事記録項目ID` | BIGINT | NOT NULL | – | PK, FK→`T食事記録項目.ID`（CASCADE） | 記録項目 | `MealRecordItemId` | – |
| 2 | `栄養素ID` | SMALLINT | NOT NULL | – | PK, FK→`T栄養素.ID` | 栄養素 | `NutrientId` | `code` |
| 3 | `量` | DECIMAL(14,4) | NOT NULL | – | | スナップショット値 | `Amount` | `amount` |
| 4 | `不完全フラグ` | TINYINT(1) | NOT NULL | 0 | | 1 = 未測定の食材を含む | `IsIncomplete` | `isIncomplete` |
| 5 | `作成日時` | DATETIME | NOT NULL | 現在日時 | | 共通 | `CreatedAt` | – |
| 6 | `更新日時` | DATETIME | NOT NULL | 現在日時（更新時も） | | 共通 | `UpdatedAt` | – |

| 制約/索引 | 内容 |
|-----------|------|
| 主キー | (`食事記録項目ID`, `栄養素ID`) |
| `FK_食事記録項目栄養素_食事記録項目` | `食事記録項目ID` → `T食事記録項目.ID`（**ON DELETE CASCADE**） |
| `FK_食事記録項目栄養素_栄養素` | `栄養素ID` → `T栄養素.ID` |

```sql
    `食事記録項目ID` BIGINT        NOT NULL,
```

## 5. MySQL 方言への対応メモ

| 項目 | 対応 |
|------|------|
| 部分インデックスなし | 既定単位の一意制約は生成列＋UNIQUE（§3.5）。メニュー/記録項目の索引は通常索引 |
| `CHECK` | 8.0.16 以降で強制される。それ未満では無視されるため、版は [11.技術スタック.md](11.技術スタック.md) で 8.4 系を想定 |
| `CHECK` と参照アクション | CHECK の対象列に `CASCADE` 等の外部キーを張れない（§3.12） |
| 生成列と外部キー | 生成列の元になる `食材ID` の外部キーは参照アクションなし（RESTRICT）にする |
| 識別子の長さ | 制約名・索引名は 64 文字以内（現在の最長は `FK_食事記録項目栄養素_食事記録項目` で収まる） |
| 照合順序 | ひらがな/カタカナの扱いは照合順序に依存する。検索の正規化は**アプリ側**で行うので照合順序に依存しない設計（要確認） |
| 構文検証 | 本書の DDL は MySQL 8 で未検証。実装時に EF Core Migrations の生成物と突き合わせ、差分があれば本書を先に直す |
