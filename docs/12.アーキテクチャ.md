## 2. バックエンドの構成

ルート名前空間: `NutritionTracker`

### 2.1 プロジェクト

| プロジェクト | 責務 | 参照してよい先 |
|--------------|------|----------------|
| `NutritionTracker.Domain` | **純粋な計算ロジック**。ASP.NET Core・EF Core・`Entities` に依存しない | なし（.NET 標準ライブラリのみ。**プロジェクト参照・パッケージ参照を持たない**ことで強制する） |
| `NutritionTracker.Api` | Web API 本体 | `Domain` |
| `NutritionTracker.Domain.Tests` | `Domain` の単体テスト（正解データ） | `Domain` |
| `NutritionTracker.Api.Tests` | API テスト（実 DB） | `Api` |

### 2.2 `NutritionTracker.Api` 内のフォルダ（名前空間）

| フォルダ | 責務 | 依存してよい先 |
|----------|------|----------------|
| `Config` | 設定クラス（Options パターンでスコア係数など: [06.スコアリング仕様.md §8](06.スコアリング仕様.md)、CORS、マスタ取り込みの有効化） | – |
| `Controllers` | REST の入出力。モデル検証、`Dtos` ↔ `Services`。**ロジックを持たない** | `Dtos`, `Services`, `Exceptions` |
| `Dtos` | リクエスト/レスポンスの型（`record`）。[09.API仕様.md](09.API仕様.md) と 1 対 1 | – |
| `Entities` | EF Core のエンティティ。テーブルと 1 対 1（[05.テーブル定義書.md](05.テーブル定義書.md)）。API に直接出さない | – |
| `Data` | `DbContext`、エンティティ設定（Fluent API で日本語名・制約・生成列を定義）、`Migrations/` | `Entities` |
| `Repositories` | 検索・集計クエリ（EF Core） | `Data`, `Entities` |
| `Services` | ユースケース（トランザクション境界）。`Repositories` と `Domain` を組み合わせる | `Repositories`, `Domain`, `Entities`, `Dtos`, `Exceptions` |
| `Exceptions` | 業務例外と、エラー形式への変換ミドルウェア: `VALIDATION_ERROR` / `NOT_FOUND` / `CONFLICT` | `Dtos` |
| `Master` | マスタ CSV と取り込み（`IHostedService`）。[07.マスタデータ仕様.md §5](07.マスタデータ仕様.md) | `Services`, `Data` |

### 2.3 `Domain` の方針（最重要）

- **フレームワークに依存しない**。入出力は不変の値オブジェクト（`record`）と `decimal` のみ。
- 副作用なし（DB・時刻・乱数を直接触らない。時刻が必要なら引数で受け取る）。
- 正解データ（[10.受け入れ基準.md §3, §4](10.受け入れ基準.md)）に対する xUnit の単体テストで網羅する。ASP.NET Core を起動しない。

| クラス（案） | 責務 | 仕様の正本 |
|--------------|------|------------|
| `UnitConverter` | 数量×単位 → `重量g` | [03.栄養計算仕様.md §2](03.栄養計算仕様.md) |
| `FoodNutritionCalculator` | 食材の栄養量（廃棄率・欠測・微量） | 同 §3, §4 |
| `MenuNutritionCalculator` | メニュー合計 | 同 §6 |
| `PortionCalculator` | `食べた割合`、残量 | 同 §6 |
| `SnapshotCalculator` | 記録時の丸め（4 桁 HALF_UP）と `不完全フラグ` | 同 §5, §6 |
| `PfcCalculator` | PFC 比 | 同 §8 |
| `TargetCalculator` | エネルギー（Mifflin-St Jeor）・タンパク質目標 | [06.スコアリング仕様.md §2](06.スコアリング仕様.md) |
| `AchievementCalculator` | 達成率（下限/範囲/上限型） | 同 §1 |
| `BeautyScoreCalculator` / `MuscleScoreCalculator` / `BaseScoreCalculator` | 3 スコア | 同 §3〜§5 |

### 2.4 レイヤ規約

- 依存方向は `Controllers → Services → Repositories / Domain`。逆方向・`Controllers` から `Repositories`/`Data` への直接依存は禁止。
- `Entities` を `Controllers` / `Dtos` に出さない（変換は `Services`）。
- 栄養値の丸めは `Domain` の 1 か所（保存時）のみ。`Services`/`Controllers`/フロントで再計算・再丸めしない（表示整形のみ可）。
- トランザクションは `Services` に置く。
- 設定値（係数・重み・閾値）はコードに埋め込まず `Config`（Options）経由（暫定値を後から差し替えやすくする）。
- 機械検証（候補）: NetArchTest でレイヤ依存と `double`/`float` 不使用を検査。`Domain` は参照を持たないことでビルド時に強制。

### 2.5 DB アクセス

- エンティティは英語の C# プロパティ名（PascalCase）とし、Fluent API で日本語のテーブル名・列名にマッピングする。**手書き SQL では識別子をバッククォートで囲む**（EF Core は自動で囲む）。
- 生成列 `既定一意キー` と CHECK 制約は `Data` の設定とマイグレーションで定義する。エンティティにはマッピングしない（[05.テーブル定義書.md §3.5](05.テーブル定義書.md)）。

## 3. フロントエンドの構成（Angular）

```
frontend/src/app/
├── api/          # HttpClient を使う API 呼び出しサービス（09.API仕様.md と 1 対 1）
├── components/   # 再利用 UI（ScoreRing, NutrientBar, FoodSearchDialog, 自前 SVG のグラフ …）。部品ごとにフォルダを分ける（例: `components/score-ring/score-ring.ts` と `score-ring.html`）
├── pages/        # 画面（SCR-01〜08 に 1 対 1）。画面ごとにフォルダを分ける（例: `pages/dashboard/dashboard.ts` と `dashboard.html`）
├── services/     # 表示整形・日付・トースト／確認ダイアログ・プロフィール保持（signals）
├── types/        # API の型。`any` 禁止、型はここに集約
└── app.config.ts / app.routes.ts
```

| ルール | 内容 |
|--------|------|
| `any` 禁止 | TypeScript `strict: true` ＋ Lint（`no-explicit-any`）。未知の値は `unknown` + 型ガード |
| 型の出どころ | API の型は [09.API仕様.md](09.API仕様.md) に合わせて `types/` に定義 |
| 計算 | 栄養・スコアの**確定値はサーバーが返す**。フロントは表示整形（丸め表示・単位）のみ。記録画面の概算 kcal は参考表示（確定値ではない） |
| 状態表現 | 色だけに頼らない（NFR-004）。`components` の共通部品（`StatusBadge` など）で文言・アイコンを必ず併記 |
| コンポーネント | standalone・`OnPush`・signals。ファイル名はケバブケースで、Angular CLI 22 の既定に合わせサフィックスなし（例: `score-ring.ts`、`dashboard.ts`。`.component` や `.page` は付けない。クラス名の `Page` は画面であることを示すために残す）。画面は 1 画面 1 フォルダ（`.ts` / `.html` / 必要なら `.css`・`.spec.ts`・ガード）に置く |
| ファイル構成 | **1 ファイル 1 コンポーネント、1 コンポーネント 1 フォルダ**（`components/` も `pages/` も同じ）。テンプレートは TypeScript に埋め込まず、`templateUrl` で別の **`.html` ファイル**にする（`score-ring.ts` と `score-ring.html`）。スタイルが必要なときは `styleUrl` で `.css` を分ける。HTML は Prettier（`.prettierrc` の `parser: angular`、空白は無視）で整形する |
| ページと SCR | ファイル先頭のコメントに SCR-ID を書く（例: `// SCR-05`）。トレース用 |

## 4. 命名規則

| 対象 | 規則 | 例 |
|------|------|----|
| DB テーブル | `T` ＋ 日本語名 | `T食事記録項目` |
| DB 列 | 日本語。主キー `ID`、外部キー `<日本語名>ID` | `食べた割合`, `メニューID` |
| DB 制約・索引 | `FK_` / `UQ_` / `IX_` / `CK_` ＋ 日本語（[05.テーブル定義書.md §1.1](05.テーブル定義書.md)） | `IX_食事記録_ユーザーID_食事日` |
| 区分値・コード値 | 英語のまま（`male`, `RATIO`, `PROT` など） | – |
| API の JSON | camelCase | `portionRatio` |
| C# クラス・メソッド・プロパティ | PascalCase | `MenuNutritionCalculator`, `PortionRatio` |
| C# ローカル変数・引数 | camelCase | `cookedTotalWeightG` |
| C# 定数 | PascalCase | `ProteinPerMealThresholdG` |
| 栄養素コード | UPPER_SNAKE_CASE（[04.データモデル.md §5](04.データモデル.md)） | `VITE_ATOC` |
| パス | 小文字ケバブ（複数形名詞） | `/api/meal-records` |
| 設定キー（`appsettings.json`） | PascalCase | `Nutrition:Scoring:Bands` |
| EF Core マイグレーション | `V<n>_<英語名>` | `V4_CreateRecordTables` |
| テスト名 | AC の ID を含める | `AC_CALC_006_OneAndHalfServing` |

C# のエンティティと API の項目名の対応は [05.テーブル定義書.md §3](05.テーブル定義書.md) の項目定義表（`C#` 列・`API` 列）を正本とする。

## 5. エラー処理

- `Services` が業務例外（`ValidationException` / `NotFoundException` / `ConflictException` 等）を投げ、`Exceptions` のミドルウェアが [09.API仕様.md §1.2](09.API仕様.md) の `{code, message, details[]}` に変換する。
- モデル検証の違反は `VALIDATION_ERROR`（`details[].field` にパス）。想定外の例外は `INTERNAL_ERROR`（詳細はログのみ）。
