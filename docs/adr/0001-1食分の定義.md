# ADR-0001: 1 食分の定義（食べた量 ÷ 完成後重量）

- 状態: 採用（D-4）
- 日付: 2026-10-17
- 関連: [03.栄養計算仕様.md §6](../03.栄養計算仕様.md) / [01.要件定義.md](../01.要件定義.md) FR-022, FR-023, FR-030

## 状況

作り置き料理は「1 人前」が曖昧で、レシピ上の人数分と実際に食べる量が一致しない。利用者は「お椀 1 杯」「鍋の 1 割」のように量を表現し、毎回 g を量るのは負担が大きい。栄養は食材ごとに計算できるが、鍋全体の栄養を「食べた分」に按分する基準が必要。

## 決定

**1 食分は「食べた量 ÷ 完成後重量」の割合（`食べた割合`）で表す。**

- メニューは完成後重量（鍋ごとの重さ − 空鍋の重さ）と杯数を持つ。
- 記録は割合（RATIO）・杯数（SERVING = 入力した杯数 ÷ メニューの杯数）・g（GRAM = g ÷ 完成後重量）のいずれかで入力し、すべて `食べた割合`（`DECIMAL(9,6)`）に正規化する。
- 栄養 = メニュー合計 × `食べた割合`。残量 = 1 − Σ`食べた割合`（保存しない）。

## 理由

- 完成後重量が分かれば、水分の蒸発や吸水による重量変化を吸収できる（食材重量の合計では按分できない）。
- 3 つの入力方式を同じ割合に正規化できるため、計算・残量管理が 1 つの式で済む。
- 「杯数」は利用者の感覚に近く、ワンタップ記録（クイックチップ）と相性が良い。

## 結果

- 完成後重量の入力がメニュー作成の必須手順になる（鍋重量の差し引き入力を UI で補助する）。
- 具と汁の偏り（具だけ多く食べる等）は表現できない（スコープ外）。
- 完成後重量が不正確だと全記録の栄養がずれる。UI で食材合計と大きく乖離する場合に注意を出す。

## 代替案

| 案 | 不採用の理由 |
|----|--------------|
| レシピの人数分（N 人前）で按分 | 実際の盛り付け量と合わない。ユーザーが人前を量りにくい |
| 食材の合計重量で按分 | 調理中の水分変化を無視し、完成品の量と一致しない |
| 毎回 g のみで記録 | 記録の手間が大きく継続しにくい |
