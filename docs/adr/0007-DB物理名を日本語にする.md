# ADR-0007: DB の物理名を日本語にする（テーブルは T 接頭辞）

- 状態: 採用（利用者の指定）
- 日付: 2026-10-17
- 関連: [05.テーブル定義書.md §1](../05.テーブル定義書.md) / [04.データモデル.md](../04.データモデル.md) / [12.アーキテクチャ.md §4](../12.アーキテクチャ.md)

## 状況

初版では DB のテーブル・列を英語の snake_case（`meal_record_items`、`portion_ratio` など）で設計していた。利用者から、テーブル名・カラム名を日本語にし、テーブル名は先頭に大文字 `T` を付けるよう指示があった（例: `users` → `Tユーザー`）。

## 決定

- テーブル名は **`T` ＋ 日本語名**（例: `Tユーザー`、`T食事記録項目`）。
- カラム名は**日本語**。主キーは `ID`、外部キーは `<参照先の日本語名>ID`（例: `ユーザーID`）。監査列は `作成日時` / `更新日時`。
- 制約・索引の名前も日本語（`FK_` / `UQ_` / `IX_` / `CK_` の接頭辞のみ英字）。
- **区分値・コード値**（`male`, `RATIO`, `RDA`, `PROT` など）と、API の JSON（camelCase）は英語のまま変更しない。DB の「名前」ではなく、データと API の契約であるため。
- C# のエンティティ・プロパティは英語（PascalCase）とし、EF Core の Fluent API で日本語名にマッピングする。

## 理由

- 業務用語（食材、メニュー、食事記録など）とテーブル・列が 1 対 1 に対応し、設計書と DB の用語の差をなくせる。
- `T` 接頭辞で、テーブルであることが名前から分かる。

## 結果

- 手書き SQL では識別子を常にバッククォートで囲む必要がある（EF Core は自動で囲む）。`100gあたり含有量` のように数字で始まる名前も、囲めば有効。
- 文字コードは `utf8mb4` を使う。識別子の長さ上限（64 文字）に注意する。
- API・C# の名前（英語）と DB の名前（日本語）の対応表が必要になる。[05.テーブル定義書.md](../05.テーブル定義書.md) の項目定義表の `C#` 列・`API` 列を正本とする。
- 日本語識別子が扱いにくい外部ツールが出た場合は、ビューで英語名を提供するなどの対応を検討する（現時点で予定なし）。

## 代替案

| 案 | 不採用の理由 |
|----|--------------|
| 英語の snake_case を維持 | 利用者の指定と異なる |
| テーブルのみ日本語、列は英語 | 利用者の指定（カラムも日本語）と異なる |
| 区分値も日本語にする | API の契約が変わり、コード中の比較も日本語になるため不採用 |
