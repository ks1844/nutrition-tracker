# ADR-0004: スコアは 100% で頭打ちにし、直近 7 日平均を主軸にする

- 状態: 採用（方式）／係数・重み・閾値は**暫定**（Q-4）
- 日付: 2026-10-17
- 関連: [06.スコアリング仕様.md](../06.スコアリング仕様.md) / [01.要件定義.md](../01.要件定義.md) FR-041, FR-043, FR-046

## 状況

スコアを単純に「摂取量÷目標の平均」にすると、過剰摂取した栄養素が他の不足を相殺する。また 1 日の摂取は日ごとの変動が大きく、1 日単位の点数に一喜一憂すると継続しにくい。食事摂取基準は習慣的な摂取量を想定している。

## 決定

1. **達成率は 100%（1.0）で頭打ち**にする（下限型: `min(摂取/目標, 1.0)`）。上限型（UL・DG_MAX）は超過時のみ警告/減点とし、他栄養素の達成率と相殺しない。
2. **評価の主軸は直近 7 日平均**（記録日のみで平均）。記録日が 3 日未満なら「データ不足」とし、スコアを出さない。
3. 当日分は「今日の進捗」として**別表示**する。UL 超過は当日値で警告する。
4. 係数・重み・閾値は `appsettings.json` の設定値にし、暫定として扱う。

## 理由

- 頭打ちにより「不足を補う」方向の行動にだけスコアが反応し、過剰摂取での水増しを防げる。
- 7 日平均は習慣的な摂取に近く、1 日の偏りに対して責めない評価になる。
- 記録していない日を 0 として平均すると、記録漏れで不当に低く出る。記録日のみで平均することで入力の負担を下げる。
- データ不足を明示することで、少ない記録からの誤った評価を避ける。

## 結果

- 記録日が少ない週はスコアが出ない（UI に説明が必要）。
- 記録日のみの平均は、記録しない日に多く食べた場合を反映できない（許容）。
- 設定値で調整できるが、変更時は [06.スコアリング仕様.md](../06.スコアリング仕様.md) と正解データ（AC-SCORE-xxx）を同時に更新する必要がある。

## 代替案

| 案 | 不採用の理由 |
|----|--------------|
| 頭打ちなし（超過も加点） | 過剰摂取で不足を相殺する |
| 当日のみで評価 | 日ごとの変動が大きく、責められる印象になりやすい |
| 7 日を毎日の分母に含める（無記録日=0） | 記録漏れで過小評価。記録の継続を阻害 |
