# ADR-0006: 技術スタックを Angular / C# / MySQL にする

- 状態: 採用（利用者の指定）
- 日付: 2026-10-17
- 関連: [11.技術スタック.md](../11.技術スタック.md) / [12.アーキテクチャ.md](../12.アーキテクチャ.md) / [05.テーブル定義書.md](../05.テーブル定義書.md)

## 状況

設計書の初版は、既存の TaskManagement に合わせて Spring Boot（Java）/ PostgreSQL / React（Vite）を前提に書かれていた。利用者から、フロントエンドは Angular、バックエンドは C#、データベースは MySQL にするとの指定があった。

## 決定

| 層 | 採用 |
|----|------|
| フロントエンド | Angular（TypeScript `strict`） |
| バックエンド | C# / ASP.NET Core Web API |
| データベース | MySQL |
| ORM・マイグレーション | Entity Framework Core / EF Core Migrations |
| ポート | バックエンド 8080 / Angular 4200 / MySQL 3306（各ツールの標準に合わせる） |

## 理由

- 利用者が使用したい（学習したい）技術であることが第一の理由。技術的な優劣で選んだものではない。
- ASP.NET Core と EF Core は C# の標準的な組み合わせで、`decimal` 型により栄養計算の精度要件（NFR-001）を満たせる。
- Angular の `strict` な TypeScript は「`any` 禁止」の方針と相性が良い。

## 結果

- Spring Boot / Java / Flyway / PostgreSQL / React / Vite を前提とした記述をすべて置き換えた（数値・計算式・API・画面の仕様は変えていない）。
- MySQL は部分インデックスに対応していないため、既定単位の一意制約は生成列＋UNIQUE で表現する（[05.テーブル定義書.md §3.5](../05.テーブル定義書.md)）。CHECK 制約には「参照アクション付き外部キー列を使えない」制約もある。
- マイグレーションは EF Core Migrations。DDL の正本は設計書（[05.テーブル定義書.md](../05.テーブル定義書.md)）に置き、生成されたマイグレーションと突き合わせる。
- Domain を別プロジェクトにして外部参照を持たせることで、Spring 非依存だった「純粋関数の計算クラス」の方針を保つ。
- MySQL のバージョン・EF Core の MySQL プロバイダ・グラフ/テストの各ライブラリは未確定（「候補」「要確認」）。

## 代替案

| 案 | 不採用の理由 |
|----|--------------|
| 従来の Spring Boot / PostgreSQL / React（TaskManagement と同じ） | 利用者の指定と異なる |
| Flyway で SQL ファイルを管理（C# でも利用可能） | C# では EF Core Migrations が標準で、Fluent API で日本語名・制約を一元管理できる。DDL の正本は設計書に置く |
| Angular の開発サーバーを従来の 5173 に合わせる | 各ツールの標準ポートに合わせる方が設定が少ない |
