# ADR-0002: 記録時に栄養スナップショットを保存する

- 状態: 採用（D-5）
- 日付: 2026-10-17
- 関連: [04.データモデル.md](../04.データモデル.md)（`T食事記録項目栄養素`）/ [03.栄養計算仕様.md §5](../03.栄養計算仕様.md) / [01.要件定義.md](../01.要件定義.md) FR-024, FR-026

## 状況

メニューは後から編集・論理削除でき、食材マスタも更新されうる。記録の栄養を「表示のたびにメニューから再計算」すると、メニューを編集した瞬間に過去の日の栄養が変わってしまう。

## 決定

**記録時に、記録項目ごとの栄養値を `T食事記録項目栄養素` へ保存（スナップショット）し、以後の集計は保存値から行う。**

- 丸めは保存時に 1 回（`DECIMAL(14,4)`、HALF_UP）。
- 全栄養素分の行を保存し、未測定を含む栄養素は `不完全フラグ = true`。
- メニュー編集・削除、マスタ更新は既存のスナップショットに影響しない。
- 記録を編集して入力が変わった項目だけ、その時点の内容で再計算して置換する（暫定）。

## 理由

- 「過去の記録は不変」（FR-024）を最も単純に保証できる。
- 集計（日次・週次）が保存値の SUM で済み、性能（NFR-002）に有利。
- 論理削除されたメニューの記録も栄養が残る。

## 結果

- 記録 1 件あたり約 24 行の保存が必要（縦持ち: [ADR-0003](0003-栄養値の縦持ち.md)）。
- 寄与食材（FR-044）は食材別の内訳を持たないため、記録項目単位で集計し、メニューの食材内訳は現在の構成から按分する参考値になる（[09.API仕様.md](../09.API仕様.md) API-19）。
- マスタの誤りを訂正しても過去の記録は自動で直らない。必要なら再計算バッチを別途作る（現状スコープ外）。

## 代替案

| 案 | 不採用の理由 |
|----|--------------|
| 毎回メニューから再計算 | メニュー編集で過去が変わる。FR-024 を満たせない |
| メニューをバージョン管理して参照 | 構造が複雑。バッチ管理を持たない方針（D-2）と合わない |
| 食材単位までスナップショット | 行数が膨らむ。MVP では寄与の精度より単純さを優先 |
