## 2. CSV 仕様

文字コード UTF-8（BOM なし）、改行 LF、ヘッダー行あり、区切りカンマ。**ヘッダー名は DB の列名（日本語）に合わせる**。配置先は `backend/src/NutritionTracker.Api/Master/`（暫定）。空欄は NULL を表す。

### 2.1 `食材.csv`（→ `T食材`）

| 列 | 型 | 必須 | 説明 |
|----|----|------|------|
| `食品コード` | 文字列 | ○ | 食品コード。upsert キー（一意） |
| `名称` | 文字列 | ○ | 画面表示名（例: にんじん） |
| `正式名称` | 文字列 | – | 成分表上の正式名称 |
| `読み仮名` | 文字列 | ○ | 読み。ひらがなで記載（取り込み時にも正規化） |
| `食品群` | 文字列 | – | 食品群 |
| `廃棄率` | 数値 | ○ | 廃棄率（%）。0 以上 100 未満、小数 1 桁 |
| `出典版` | 文字列 | ○ | 出典の版（Q-1 確定後に値を決める） |
| `有効フラグ` | 0/1 | – | 既定 1 |

### 2.2 `食材栄養素.csv`（→ `T食材栄養素`）

| 列 | 型 | 必須 | 説明 |
|----|----|------|------|
| `食品コード` | 文字列 | ○ | `食材.csv` の `食品コード` |
| `栄養素コード` | 文字列 | ○ | [04.データモデル.md §5](04.データモデル.md) の栄養素コード |
| `成分表表記` | 文字列 | ○ | **成分表の表記そのまま**（記号を含む）。変換は §3 の規則で取り込み時に行う（DB の列ではない） |
| `出典メモ` | 文字列 | – | 200 文字以内。出典の補足（ページ・脚注など） |

> `成分表表記` を保持する CSV にすることで、原典との突き合わせと変換規則の自動テストを可能にする。DB には変換後の値（`100gあたり含有量`, `微量フラグ`）を入れる。

### 2.3 `食材単位.csv`（→ `T食材単位`）

| 列 | 型 | 必須 | 説明 |
|----|----|------|------|
| `食品コード` | 文字列 | ○ | – |
| `単位名` | 文字列 | ○ | 例: 本、個、大さじ、小さじ、枚 |
| `1単位あたりグラム` | 数値 | ○ | 1 単位のグラム数（**廃棄部込み**）。0 より大きい |
| `既定フラグ` | 0/1 | – | 食材ごとに高々 1 件が 1 |
| `根拠メモ` | 文字列 | – | 決め方・出典のメモ（DB には入れない。監査用） |

### 2.4 `食材別名.csv`（→ `T食材別名`）

| 列 | 型 | 必須 | 説明 |
|----|----|------|------|
| `食品コード` | 文字列 | ○ | – |
| `別名` | 文字列 | ○ | 別名（かな・カナ・漢字・通称）。原表記のまま保存 |

### 2.5 `栄養目標.csv`（→ `T栄養目標`）

| 列 | 型 | 必須 | 説明 |
|----|----|------|------|
| `栄養素コード` | 文字列 | ○ | – |
| `性別` | 文字列 | ○ | `male` / `female` / `all` |
| `年齢下限` / `年齢上限` | 整数 | ○ | 上限なしは 999 |
| `種別` | 文字列 | ○ | `RDA` / `AI` / `DG_MIN` / `DG_MAX` / `UL` |
| `目標値` | 数値 | ○ | 目標値（**Q-2: 公式の表から転記。確証のない値は入れない**） |
| `単位基準` | 文字列 | ○ | `PER_DAY` / `PER_KG_BW` / `PCT_ENERGY` |
| `出典メモ` | 文字列 | – | 食事摂取基準 2025 年版の表名・ページなど |

`ENERGY` と `PROT` はプロフィールから算出する（[06.スコアリング仕様.md §2](06.スコアリング仕様.md)）。`ENERGY` には `DG_*` を登録しない。

## 3. 成分表記号の変換規則（`成分表表記` → DB）

**いずれも要原典確認**（成分表の凡例と突き合わせて確定する）。

| 成分表の表記 | `100gあたり含有量` | `微量フラグ` | 備考 |
|--------------|--------------------|--------------|------|
| `-`（未測定） | NULL | 0 | 0 ではない。計算時は `不完全フラグ` を立てる |
| `Tr`（微量） | 0 | 1 | 検出限界未満 |
| `(0)`（推定値 0） | 0 | 0 | 推定値 |
| `(数値)`（推定値） | 括弧を除いた数値 | 0 | 例: `(1.2)` → 1.2 |
| `数値` | その数値 | 0 | – |
| 空欄 | NULL | 0 | `-` と同様に未測定として扱う（要確認） |
| 上記以外 | **取り込みエラー** | – | 検証ルール（§7）で失敗にする。`(Tr)` のような括弧つきの記号もエラー（原典で確認して必要なら規則を足す） |

- 推定値であること自体は `出典メモ` に残してよい（DB のフラグは持たない）。
- 数値の全角・カンマ（`1,000`）は半角・カンマ除去してから解釈する。全角のハイフン類（`－` `‐` `−` `ー`）は `-`（未測定）として扱う。
- 実装: `NutritionTracker.Domain.Nutrition.FoodTableNotation`（取り込み処理から使う純粋関数。単体テストで規則を検証）。

## 4. 換算単位

| 項目 | 方針 |
|------|------|
| 出典 | 一般的な目安量（市販品の表示、調理の目安表 等）。**食材ごとに別の値**を設定する（同じ「1 個」でも食材で異なる） |
| 重量の定義 | **廃棄部込み**（皮・種・ヘタを含む購入時の重さ）。栄養計算では廃棄率を後から差し引く |
| 例（テスト用） | にんじん 1 本 = 150g、みそ 大さじ 1 = 18g（[03.栄養計算仕様.md §9](03.栄養計算仕様.md)。実在の値と一致する保証はない） |
| 根拠の記録 | `根拠メモ`（CSV のみ）に出典または決め方を書く。出典不明の値は「暫定」と明記 |
| 既定単位 | 食材ごとに高々 1 つ `既定フラグ` を 1 にする（DB でも一意制約: [05.テーブル定義書.md §3.5](05.テーブル定義書.md)） |
| 追加 | MVP では CSV 更新のみ（利用者の追加はスコープ外） |

## 5. 取り込み方式

| 項目 | 方針 |
|------|------|
| 冪等性 | `食品コード` で upsert。再実行しても結果が同じ（`T食材栄養素` は (`食材ID`, `栄養素ID`)、`T食材単位` は (`食材ID`, `単位名`)、`T食材別名` は (`食材ID`, `別名`) で upsert）。MySQL では `INSERT … ON DUPLICATE KEY UPDATE` または EF Core での存在確認＋更新 |
| 実行方法 | **起動時の `IHostedService`（ASP.NET Core のホステッドサービス）を暫定採用**。マイグレーション（EF Core Migrations）は構造と `T栄養素` の初期データのみを管理する。代替案: マイグレーション内でのデータ投入（バージョン管理されるが、CSV 更新のたびに新しいマイグレーションが必要になる） |
| 起動制御 | 設定 `Nutrition:MasterImport:Enabled`（既定 true）と `Nutrition:MasterImport:Path`（既定 `Master`。相対パスはコンテンツルート＝開発時はプロジェクトのフォルダから）で切り替える。CSV が 1 つも無ければスキップする。手動実行は未実装（暫定） |
| 削除 | CSV から消えた食材は物理削除せず `有効フラグ` を 0 にする。食材の子（栄養素・単位・別名）と栄養目標は upsert のみで、CSV から消えても削除しない（メニューや記録から参照されている可能性があるため） |
| 既定単位 | CSV に単位がある食材は、いったん既定フラグをすべて外してから CSV の指定を反映する（付け替えが一意制約に触れないため）。CSV に単位が無い食材の既定単位は変えない |
| 失敗時 | 検証エラーが 1 件でもあれば**何も書き込まず**（検証は書き込み前にすべて行う）、`ファイル名 n行目: …` の形で全件をログに出し、**アプリは起動しない**。書き込み中の失敗は 1 トランザクションでロールバックする |
| 実データの置き場 | `backend/src/NutritionTracker.Api/Master/`。CSV は `.gitignore` で除外する（§8）。ダミーの例はテスト（`MasterImportTests`）にある |
| テストデータ | テスト用ダミー食材（F1〜F3）はテストプロジェクト側に置き、本番マスタ CSV に混ぜない |

## 6. アスタキサンチン（Q-3）

| 案 | 内容 | 長所 | 短所 |
|----|------|------|------|
| A: 参考値案 | `T栄養素` の `ASTX`（`参考値フラグ`=1）を残し、数食品（鮭・えび等）だけ文献値を `出典メモ` 付きで入れる。**スコアには含めない** | 参考情報を出せる | 出典の信頼性確認が必要。成分表と同列に見えない表示が必要 |
| B: 見送り案 | MVP では ASTX を取り込まない（栄養素行は残すが値なし）。画面にも出さない | 出典問題を避けられる | 美肌の訴求が弱くなる |

- 成分表八訂には記載がない想定（要確認）。どちらの案でも**スコア外**。
- 参考値には画面で「参考値（成分表外）」と明記する。決定は Q-3 で行い、決まるまでは A の枠組み（`参考値フラグ`）だけを実装しておく。

## 7. 取り込み時の検証ルール

| # | ルール | 違反時 |
|---|--------|--------|
| V-1 | `食品コード` が一意で、他 CSV の `食品コード` が `食材.csv` に存在する | エラー |
| V-2 | `栄養素コード` が [04.データモデル.md §5](04.データモデル.md) に存在する | エラー |
| V-3 | `成分表表記` が §3 のいずれかの形式に一致する | エラー |
| V-4 | `廃棄率` が 0 以上 100 未満 | エラー |
| V-5 | `1単位あたりグラム` > 0、同一食材で `単位名` が重複しない、`既定フラグ` が 1 のものが 2 件以上ない | エラー |
| V-6 | `出典版` が空でない（NFR-008） | エラー |
| V-7 | 食材ごとに `ENERGY` / `PROT` / `FAT` / `CHO` の行が存在する（値が `-` でも行は必須） | 警告 |

| V-9 | 負の値がない | エラー |
| V-10 | `栄養目標.csv` の (`栄養素コード`, `性別`, `年齢下限`, `年齢上限`, `種別`) が一意で、年齢範囲に矛盾がない | エラー |

## 8. ライセンス・出典表記（Q-1）

- 成分表（日本食品標準成分表）の利用条件・出典表記の要否・再配布の可否は**要確認**。リポジトリは公開のため、確認が取れるまで**成分値そのものをコミットしない**運用を検討する（CSV はローカル配置にするか、利用条件に従う）。
- 確認が取れたら、版名・出典表記文言を本書に追記し、`出典版` の値を確定する。
