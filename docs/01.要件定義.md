# 要件定義

- 状態: ドラフト / 最終更新: 2026-10-17
- 索引: [README.md](README.md) / 用語: [02.用語集.md](02.用語集.md)

## 1. 目的

自炊（特に作り置き）中心の人が、**「鍋いっぱいに作った料理を、何割・何杯食べたか」で簡単に記録**し、栄養の過不足を**責めない表現で**確認できるようにする。

- 作り置きは「1 人前の量」が曖昧になりやすい。完成後重量と杯数（または割合）で 1 食分を定義し、記録の手間を最小化する（[ADR-0001](adr/0001-1食分の定義.md)）。
- 美肌・筋肉・基礎栄養の 3 つのスコアで、直近 7 日の傾向と今日の進捗を見せる（[06.スコアリング仕様.md](06.スコアリング仕様.md)）。
- 本アプリは学習用の個人開発であり、**食事摂取基準に基づく目安の提示**に留まる。医療的助言ではない（FR-047）。

## 2. ユーザー像

| 項目 | 内容 |
|------|------|
| 属性 | 週末などにまとめて調理して作り置きする自炊派。一人暮らし〜少人数世帯 |
| 目的 | 美肌（skin）／筋肉（muscle）／両方（both）のいずれかを意識した食事 |
| 利用環境 | 主にスマートフォン（幅 375px）。食後にその場で記録 |
| 悩み | 作り置きの 1 食分の栄養が分からない／毎回 g を量るのは面倒／不足栄養素に気付けない |
| MVP の前提 | 固定ユーザー 1 名（D-1、[ADR-0005](adr/0005-MVPは固定ユーザー.md)） |

## 3. 代表シナリオ

| ID | シナリオ | 主な FR | 主な画面 |
|----|----------|---------|----------|
| S-1 | **初回設定**: 性別・生年月日・身長・体重・活動レベル・目的を入力し、エネルギー・タンパク質などの目標が自動算出されるのを確認する。必要ならエネルギー目標を手動で上書きする | FR-001, FR-002 | SCR-01 |
| S-2 | **作り置きを登録**: 豚汁の食材（にんじん 2 本、豚こま 400g、みそ大さじ 4）を検索して追加し、リアルタイムに栄養を確認。鍋ごとの重さから空鍋を引いて完成後重量を入力し、8 杯分（お椀 1 杯 = 300g）と定義する | FR-010, FR-020〜FR-023 | SCR-05 |
| S-3 | **食べて記録**: 夕食に豚汁をお椀 1.5 杯食べたとしてワンタップで記録。ホームの残量カードから「+1 杯」で追加記録もできる。ご飯など単品食材は g で記録する | FR-030〜FR-032, FR-037 | SCR-02, SCR-03 |
| S-4 | **1 日の確認**: ホームとダッシュボードで kcal・PFC・3 スコア・栄養素ごとの達成率を見る。不足は青系、達成は緑系で、数値と文言も併記。UL 超過は警告表示。欠測のある栄養素には注記が出る | FR-040〜FR-042, FR-046, FR-047 | SCR-02, SCR-06 |
| S-5 | **週の振り返り**: 直近 7 日平均に切り替え、スコア推移と、不足栄養素に寄与している食材を確認。作り置きの残量を見て、次の調理（複製して再作成）の参考にする | FR-043〜FR-045, FR-025, FR-027 | SCR-04, SCR-06, SCR-07, SCR-08 |

## 4. 機能要件

優先度: **M**=Must（MVP 必須）/ **S**=Should（できれば MVP）/ **C**=Could。D-3 により MVP は Must を対象とし、Should は余力で追加する。

### 4.1 プロフィール・目標

| ID | 要件 | 優先度 |
|----|------|--------|
| FR-001 | プロフィール（性別・生年月日・身長・体重・活動レベル・目的 skin/muscle/both）を登録・更新できる | M |
| FR-002 | プロフィールから栄養目標を自動算出する。エネルギー目標は手動で上書きできる（[06.スコアリング仕様.md §2](06.スコアリング仕様.md)） | M |

### 4.2 食材

| ID | 要件 | 優先度 |
|----|------|--------|
| FR-010 | 食材をかな・カナ・漢字・別名で検索できる | M |
| FR-011 | 食材詳細（栄養素・廃棄率・換算単位・出典/版）を表示できる | S |

### 4.3 メニュー（作り置き）

| ID | 要件 | 優先度 |
|----|------|--------|
| FR-020 | メニューを作成できる。食材量は g または単位（大さじ、本 等）で入力できる | M |
| FR-021 | 食材追加・変更に応じて栄養をリアルタイムにプレビューする（未保存でも計算できる） | M |
| FR-022 | 完成後重量を入力できる（鍋ごとの重さ − 空鍋の重さ） | M |
| FR-023 | 1 食分を定義できる（杯数とラベル。例: 8 杯分・お椀） | M |
| FR-024 | メニューを編集できる。編集しても過去の記録は変わらない（[ADR-0002](adr/0002-栄養スナップショット.md)） | M |
| FR-025 | メニューを複製できる（作り置きの再作成は複製で代替。D-2） | M |
| FR-026 | メニューを論理削除できる。過去の記録は残る | M |
| FR-027 | メニューの残量（割合・杯数）を表示できる | S |

### 4.4 食事記録

| ID | 要件 | 優先度 |
|----|------|--------|
| FR-030 | メニューを割合・杯数・g のいずれかで記録できる | M |
| FR-031 | 単品食材を記録できる（g または単位） | M |
| FR-032 | 1 回の食事（朝昼夕・間食）に複数品を記録できる | M |
| FR-033 | 記録を編集・削除できる | M |
| FR-034 | メニューの合計記録が 100% を超える場合に警告を出す（保存はブロックしない） | S |
| FR-035 | 「最近使った」食材・メニューから素早く記録できる | S |
| FR-036 | 「昨日と同じ」で前日の記録をコピーできる | S |
| FR-037 | 残量カードから「+1 杯」で追加記録できる | S |

### 4.5 サマリ・スコア

| ID | 要件 | 優先度 |
|----|------|--------|
| FR-040 | 日次サマリ（kcal・PFC・PFC 比）を表示する | M |
| FR-041 | 美肌・筋肉・基礎の 3 スコアを表示する（[06.スコアリング仕様.md](06.スコアリング仕様.md)） | M |
| FR-042 | 栄養素ごとの達成率バーと UL 超過警告を表示する | M |
| FR-043 | 「今日」と「直近 7 日平均」を切り替えて表示する | M |
| FR-044 | 栄養素ごとの寄与食材（何から摂れているか）を表示する | S |
| FR-045 | 7 日間のスコア・kcal 推移を表示する | S |
| FR-046 | 欠測・データ不足の注記を表示する（未測定を含む栄養素、記録日が少ない場合） | M |
| FR-047 | 免責文（食事摂取基準に基づく目安であり医療的助言ではない）を表示する | M |

## 5. 非機能要件

| ID | 区分 | 要件 |
|----|------|------|
| NFR-001 | 計算精度 | 栄養計算・スコアは DB では DECIMAL、アプリでは `decimal`（C#。丸めは四捨五入 = HALF_UP）で行う。float/double を使わない（[03.栄養計算仕様.md](03.栄養計算仕様.md)） |
| NFR-002 | 性能 | 食材 300 件・記録 1 年分のデータ量で、各 API が 1 秒以内に応答する |
| NFR-003 | モバイル | 幅 375px の画面で主要操作（記録・メニュー作成・サマリ確認）が完結する |
| NFR-004 | アクセシビリティ | 状態（不足/達成/超過）を色だけで表現せず、アイコン・文言・数値を併記する |
| NFR-005 | テスト容易性 | 栄養計算・スコアは正解データ（[10.受け入れ基準.md](10.受け入れ基準.md)）に対する自動テストで検証する |
| NFR-006 | コスト | AWS は固定費の高い構成を避ける（EC2 t2.micro と RDS 各 1 台、ロードバランサ・NAT なし、自分の IP のみ許可）。リソース作成前に費用を確認し、動作確認後は速やかに破棄する（[14.デプロイ設計.md](14.デプロイ設計.md)） |
| NFR-007 | セキュリティ | 公開リポジトリのため、シークレット・個人情報をコミットしない |
| NFR-008 | データ出典 | 成分値は出典と版（`出典版`、`出典メモ`）を保持する（[07.マスタデータ仕様.md](07.マスタデータ仕様.md)） |

## 6. スコープ外

| 項目 | 備考 |
|------|------|
| ユーザーによる食材の追加 | 食材はマスタ提供のみ |
| 調理損失の補正 | 計算では無視し、画面に注記する |
| 具と汁の分離記録 | 常にメニュー全体で按分 |
| 外食・バーコード入力 | – |
| 「あと一品」提案 | – |
| レシピのバッチ管理 | 複製で代替（D-2） |
| 複数ユーザー・認証 | MVP は固定ユーザー（D-1、Q-6） |
| 廃棄・おすそ分けの記録 | 残量は「1 − 記録済み割合」で単純計算 |
| 医療助言 | 目安の提示のみ（FR-047） |
| 多言語対応 | 日本語のみ |
| 定番セット（複数品の組み合わせ保存） | 「昨日と同じ」（FR-036）で代替。保存型は対象外 |

## 7. 前提

- 栄養成分は日本食品標準成分表（八訂）を想定するが、**版と利用条件は未確認**（Q-1）。
- 栄養目標の数値は日本人の食事摂取基準（2025 年版）を想定するが、**転記は未実施**（Q-2）。本書は数値を記載しない。
- 食材は頻用 150〜300 食品に絞る（[07.マスタデータ仕様.md](07.マスタデータ仕様.md)）。
- 技術スタックは フロント=Angular、バック=C#（ASP.NET Core）、DB=MySQL（[11.技術スタック.md](11.技術スタック.md)、[ADR-0006](adr/0006-技術スタックの選定.md)）。
- ポートは 8080（バックエンド）/ 4200（Angular 開発サーバー）/ 3306（MySQL）固定。
