# 栄養計算仕様

- 状態: ドラフト / 最終更新: 2026-10-17
- **栄養計算の正本**。実装は `domain` パッケージの純粋関数（[12.アーキテクチャ.md](12.アーキテクチャ.md)）、期待値は §9 の正解データ。
- 関連: [04.データモデル.md](04.データモデル.md) / [10.受け入れ基準.md](10.受け入れ基準.md)（AC-CALC-xxx）/ [ADR-0001](adr/0001-1食分の定義.md) / [ADR-0002](adr/0002-栄養スナップショット.md)

## 1. 基本方針

| 項目 | 決定 |
|------|------|
| 数値型 | DB は DECIMAL、アプリは `decimal`（C#。NFR-001）。`double`/`float` 禁止 |
| 入力重量 | 利用者が入力する重量は**すべて廃棄前重量** |
| 丸め | **保存時に 1 回だけ**。途中では丸めない（§5） |
| 丸めモード | HALF_UP（四捨五入）。C# では `Math.Round(x, n, MidpointRounding.AwayFromZero)`（栄養値は非負なので HALF_UP と等価） |
| 調理損失 | 無視する。画面に「調理による栄養の変化は考慮していません」と注記する |
| 成分表の値 | 本書の数値例は**テスト用ダミー値**であり、実際の成分表の値ではない |

## 2. 単位換算

| 入力 | 換算 |
|------|------|
| g 入力 | `重量g = quantity` |
| 単位入力 | `重量g = quantity × T食材単位.1単位あたりグラム` |

- `1単位あたりグラム` は**廃棄部込み**の重さ（例: にんじん 1 本 = 150g は皮などを含む）。
- `Tメニュー食材.重量g` は換算済みの値を保存し、**以後の計算はこれを正とする**（換算単位マスタが後から変わっても過去のメニューが変わらない）。
- 換算結果は `DECIMAL(8,2)` に HALF_UP で丸めて保存する（換算の丸めはこの 1 回のみ）。

## 3. 食材単位の栄養量

```
可食部重量 (g)   = 重量g × (1 − 廃棄率 / 100)
栄養量 (nutrient) = 可食部重量 ÷ 100 × 100gあたり含有量
```

- 食材の栄養量は**丸めずに**保持する（`decimal` の厳密積。`/100` は小数点の移動で厳密）。
- `T食材栄養素` に行が無い栄養素は「未測定」として扱う（§4）。

## 4. 欠測・微量

| 成分表上の状態 | DB の表現 | 計算上の扱い | 表示 |
|----------------|-----------|--------------|------|
| 数値あり | `100gあたり含有量` = 値 | そのまま使用 | 値 |
| 未測定（`-`） | `100gあたり含有量` = NULL | **0 として合算**し、結果に `不完全フラグ = true` を立てる | 値 + 「※未測定の食材を含む」 |
| 微量（`Tr`） | `100gあたり含有量` = 0, `微量フラグ` = true | 0 として合算（`不完全フラグ` は立てない） | 値（0 と区別できる注記は食材詳細のみ） |
| 行なし | – | 未測定と同じ | 未測定と同じ |

- `不完全フラグ` は **OR で伝播**する: メニュー合計 → 記録項目 → 日合計 → 週平均のいずれも、1 つでも incomplete なら true。
- 0 と未測定を混同しないこと（未測定を 0 として合算するのは合算の都合であり、`不完全フラグ` が必須の目印になる）。

## 5. 丸め

| 場面 | 桁 | 備考 |
|------|----|------|
| 換算 g | 小数 2 桁（`DECIMAL(8,2)`） | §2 |
| `食べた割合` | 小数 6 桁（`DECIMAL(9,6)`） | §6。HALF_UP |
| 食材・メニューの栄養量（計算途中） | **丸めない** | – |
| スナップショット保存 | 小数 4 桁（`DECIMAL(14,4)`） | HALF_UP。**丸めはここで 1 回** |
| 表示 | 栄養素ごとに小数 1 桁（kcal は整数） | HALF_UP。保存値から作る |

- 日合計・週平均は**保存済みスナップショット（4 桁）の合計**から求める。
- 表示用の丸めを計算に戻さない。

## 6. メニューと食べた割合

```
メニュー合計(nutrient) = Σ 食材の栄養量              （丸めない）
1 回の記録(nutrient)   = メニュー合計 × 食べた割合  → 4 桁に HALF_UP して保存
```

`食べた割合` の求め方（D-4: 食べた量 ÷ 完成後重量）:

| `入力方式` | `入力値` | `食べた割合` |
|--------------|---------------|-----------------|
| `GRAM` | 食べた g | `入力値 ÷ 完成後重量g`（小数 6 桁 HALF_UP） |
| `SERVING` | 杯数 | `入力値 ÷ メニューの杯数`（小数 6 桁 HALF_UP） |
| `RATIO` | 割合（1 = 全量） | `入力値` そのもの |

- 計算には**丸め後の 6 桁の `食べた割合`** を使う（保存値と再計算値が一致するため）。
- `食べた割合` は 1 を超えうる（FR-034 は警告のみ。ブロックしない）。
- **残量 = 1 − Σ（そのメニューの有効な記録項目の `食べた割合`）**。保存しない（FR-027）。負になる場合は 0 以下を「超過」として表示する。
- 1 杯の重さ = `完成後重量g ÷ 杯数`（表示用。例: 2400 ÷ 8 = 300g）。

## 7. 単品食材の記録（FR-031）

メニューと同じ式を使う。`食べた割合` は使わず `重量g` で計算する。

```
記録(nutrient) = 重量g × (1 − 廃棄率/100) ÷ 100 × 100gあたり含有量   → 4 桁に HALF_UP
```

## 8. 派生値

| 値 | 式 | 備考 |
|----|----|------|
| PFC 比 | P 比 = `PROT×4 ÷ (PROT×4 + FAT×9 + CHO×4)` など | P,C は 4kcal/g、F は 9kcal/g。**kcal 自体は成分表の `ENERGY` を使う**（PFC 比とは別計算）。分母 0 のときは未計算 |
| 日合計 | 同日の記録項目スナップショットの合計 | – |
| 記録時の編集 | 記録項目の入力値を変更したときは、**その時点のメニュー内容で再計算**してスナップショットを置き換える（暫定）。入力が同じなら変更しない | メニュー編集は既存スナップショットに影響しない |
| 寄与食材（FR-044） | 記録項目単位（メニューまたは単品食材）はスナップショットから集計。メニューの食材内訳は**メニューの現在の構成**から按分する（暫定: 記録後にメニューを編集していると実際とずれる場合がある） | [09.API仕様.md](09.API仕様.md) API-19 |
